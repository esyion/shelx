## 1. 概述

### 1.1 产品定位

shelx 是一款**一体化服务器管理工具**:SSH 终端、SFTP 文件管理、服务端实时监控三大能力集成在一个客户端中,面向需要频繁登录和管理 Linux 服务器的开发者和运维人员。

对标产品:FinalShell、Tabby、electerm、WindTerm、Xshell。

核心差异化:

- **轻量**:Tauri 2 + 系统 WebView,内存占用显著低于 Electron 系竞品(Tabby/electerm)
- **纯净**:无广告、无强制登录、无云上报,所有数据本地存储
- **开源**:代码可审计,凭据存储方式透明
- **中文场景友好**:原生 GBK 编码支持,解决国内老服务器中文乱码痛点

### 1.2 目标用户

- 后端开发者:日常登录服务器查日志、改配置、传文件
- 初级运维:管理几台到几十台服务器,需要直观的资源监控
- 全栈/独立开发者:自建服务、部署产物上传

### 1.3 竞品参考

| 竞品 | 借鉴点 | 避免的缺点 |
|------|--------|-----------|
| FinalShell | 三合一布局、监控面板信息密度 | 闭源、内存占用高、卡顿 |
| Tabby | 连接管理、插件化设置项 | Electron 内存大户 |
| electerm | 双栏 SFTP 交互 | 传输性能一般 |
| WindTerm | 终端性能与细节打磨 | 界面复杂、上手成本高 |

## 2. 问题陈述(Problem Statement)

从用户视角,现有工具存在以下痛点:

1. **FinalShell 闭源且资源占用高**:Java 客户端常驻内存大,界面卡顿,凭据存储方式不透明,且存在广告与付费墙;用户担心密码安全但别无选择。
2. **Xshell 商业收费**:个人免费版有窗口/标签数量限制,公司使用需付费。
3. **Electron 系竞品(Tabby/electerm)内存占用大**:挂十几台服务器后轻松吃掉 1GB+ 内存。
4. **工具割裂**:终端用 Xshell、传文件用 WinSCP、看监控上宝塔——同一台服务器要在三个工具间来回切换,连接信息维护三份。
5. **中文编码问题**:国内大量历史服务器默认 GBK,主流 SSH 客户端切换编码繁琐,中文乱码是高频吐槽点。

**一句话**:用户需要一个**轻量、安全、免费、开箱即用**的 SSH + SFTP + 监控三合一桌面工具。

---

## 3. 解决方案(Solution)

shelx 以 Tauri 2 构建单窗口桌面应用,单条 SSH 连接复用承载终端、SFTP、监控三类通道,提供:

1. **连接管理器**:左侧栏树形管理服务器连接(分组、搜索、私钥/密码/动态口令认证),凭据存入操作系统钥匙串。
2. **SSH 终端**:多标签终端,基于 xterm.js,支持 GBK/UTF-8 编码切换、主题、断线重连。
3. **SFTP 文件管理**:本地/远程双栏文件管理器,拖拽上传下载,带传输队列和进度中心。
4. **服务端监控**:免 Agent,通过 SSH 执行只读命令采集 CPU/内存/网络/磁盘/负载,Recharts 实时曲线,不依赖服务器安装任何组件。

- **P1(应该有)**:v1.0 正式版包含,对应 M4
- **P2(后续迭代)**:v1.x 路线图,本 PRD 仅记录不展开

| 模块 | P0 | P1 | P2 |
|------|----|----|----|
| 连接管理 | 密码/私钥/键盘交互认证、分组、搜索、主机指纹确认、克隆、备注、快速连接 | 导入/导出(含 FinalShell 格式)、标签 tags、连接测试按钮 | 从 ssh config 导入、跳板机 |

| 服务端监控 | CPU/内存/Swap/网络/磁盘/负载实时图表、采样间隔可调、系统信息展示、断线暂停恢复 | 进程列表(排序查看)、会话内 1 小时历史回看、多服务器总览面板 | 阈值告警通知、历史持久化 |
| 通用/设置 | 深色/浅色主题、中文界面、终端默认设置、关闭标签确认 | 英文界面、全局快捷键、自动更新、安装包三平台 | 系统托盘后台传输、插件系统 |

## 5. 用户故事(User Stories)

### 5.1 连接管理

1. 作为运维工程师,我想保存服务器连接信息(主机/端口/用户名/认证方式),以便下次一键连接而不用重复输入。
2. 作为运维工程师,我想用账号密码连接服务器,这是最基本的认证方式。
3. 作为开发者,我想用私钥(含带 passphrase 的 OpenSSH 格式)连接服务器,生产环境都禁用了密码登录。
4. 作为开发者,我想在服务器要求动态口令(OTP)时弹出输入框完成键盘交互(keyboard-interactive)认证,公司服务器都套了 OTP。
5. 作为运维工程师,我想把连接按项目/环境分组成文件夹树,并支持拖拽调整位置,几十台服务器才不会乱。
6. 作为用户,我想在侧栏顶部输入关键字即时过滤连接(匹配名称/主机/IP/备注),快速定位目标。
7. 作为开发者,我想克隆一条连接只改端口来区分测试/生产库,不用从零新建。
8. 作为运维工程师,我想给连接写备注(如"双十一扩容临时机,12月回收"),避免遗忘背景。
9. 作为安全敏感的用户,我想让密码和私钥口令保存在操作系统钥匙串(Windows 凭据管理器/ macOS Keychain / Linux Secret Service)而不是明文配置文件,降低泄露风险。
10. 作为用户,我想把连接配置导出成一个文件,在新电脑上导入即可完成迁移。
11. 作为用户,我想使用"快速连接":临时输入 host/user/port 直接连上,不保存任何配置,适合帮别人排查问题。
12. 作为安全敏感的用户,首次连接陌生服务器时,我想看到主机公钥指纹(SHA256)并确认后才继续,防止中间人攻击。
13. 作为用户,我想双击连接直接打开终端标签,单击只是选中查看详情。
14. 作为用户,我想在连接编辑对话框里点"测试连接"立即验证配置是否正确,不用保存后再试。
15. 作为用户,我想给连接打彩色标签(生产/测试/危险),在列表里一眼区分环境。

## 6. 功能详细规格

### 6.1 整体布局与导航

单主窗口,区域划分:

```
┌────────────────────────────────────────────────────────┐
│  顶部:标签栏(终端标签,+,状态圆点)                      │
├──────────┬─────────────────────────────────────────────┤
│          │                                             │
│  左侧栏   │            主工作区                          │
│  连接树   │   (终端 / SFTP / 监控 三个可切换视图)          │
│  搜索框   │                                             │
│          │                                             │
├──────────┴─────────────────────────────────────────────┤
│  底部(可折叠):SFTP 双栏面板 或 传输中心(互斥切换)        │
└────────────────────────────────────────────────────────┘
```

- **左侧栏**:宽度可拖拽调整,可整体折叠(快捷键 Ctrl+B);连接树 + 底部"快速连接"按钮。
- **主工作区**:每个标签对应一条连接的工作区,内部三个视图切换:**终端**(默认)、**监控**、**文件**。切换方式:工作区顶部小型分段控件,或快捷键 Alt+1/2/3。
- **底部面板**:SFTP 双栏 与 传输中心 两个互斥页签,Ctrl+J 切换显示/隐藏。
- **监控侧栏(P1)**:终端视图下可在右侧展开一个窄监控条(迷你 CPU/内存/网速),满足"边敲命令边看负载"。

布局状态(面板显隐、宽度、当前视图)持久化,重启恢复。

### 6.2 连接管理

**数据模型**:连接(ConnConfig)+ 分组(Group)构成树;分组可嵌套一层(P1 放开多层);连接必有名称与主机,其余可选。

**新建/编辑对话框字段**:

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 名称 | 文本 | ✓ | 列表显示名 |
| 分组 | 树选择 | | 默认根目录 |
| 主机 | 文本 | ✓ | IP 或域名 |
| 端口 | 数字 | ✓ | 默认 22 |
| 用户名 | 文本 | ✓ | |
| 认证方式 | 单选 | ✓ | 密码 / 私钥 / 键盘交互(OTP)/ 免密(已配 ssh-agent 或默认密钥) |
| 密码 | 密文 | | 存钥匙串;支持"只存本次会话"选项 |
| 私钥文件 | 文件选择 | | 默认提示 `~/.ssh/id_ed25519` 等常见路径 |
| 私钥口令 | 密文 | | 存钥匙串 |
| 编码 | 下拉 | | UTF-8(默认)/ GBK |
| 标签颜色 | 色块 | | P1 |
| 备注 | 多行文本 | | |

**交互细节**:

- 保存时密码/口令写入 OS 钥匙串,连接记录中只存钥匙串引用键;钥匙串不可用时降级为机器指纹派生密钥加密存储,并在设置页显著提示。
- 主机指纹(TOFU):首次连接弹出确认框,显示算法 + SHA256 指纹;确认后记录。后续连接指纹变化时**红色警告阻断**,必须手动确认才能继续。
- 认证失败:区分"密码错误""私钥口令错误""服务器拒绝认证方式"给出对应提示,支持原地重试输入。
- 键盘交互:后端把服务器的 prompt 逐个抛给前端,以模态框(非终端内)收集输入,支持隐藏输入(密码型 prompt)。
- 快速连接:侧栏按钮或 Ctrl+Shift+C 打开轻量弹窗(主机/端口/用户/认证),连接后创建的标签标记为"临时",不进连接树。
- 删除连接:二次确认;仅删除配置,不影响钥匙串条目清理策略(设置里提供"清理孤儿凭据")。

### 6.3 SSH 终端

- **渲染**:`@xterm/xterm` + WebGL 渲染器(失败降级 Canvas);`addon-fit` 自适应容器尺寸,窗口缩放/分屏调整时向服务端发送窗口变更(pty request)。
- **数据流**:前端输入字节 → command 写入后端 → russh channel;服务端输出 → 后端按批(≤16ms 或 ≤64KB 聚合)经 ipc Channel 推给前端 → 写入 xterm。**高频流一律走 Channel,不走全局事件**,避免跨标签广播开销。
- **编码**:终端数据以**字节流**端到端传输,不破坏二进制正确性;显示编码由前端解码(UTF-8 / GBK,经 encoding_rs 的 WebAssembly 构建),切换即时生效不清屏。
- **多终端**:同一连接的多个终端 = 同一 SSH 连接上的多个 channel,互不影响。
- **断线处理**:心跳/读写错误检测到断开 → 标签状态点变红 + 终端顶部横幅("连接已断开 · [重新连接]"),终端内容保留可复制;重连成功新开 channel 并恢复视图,失败保留横幅可再试。自动重连默认关闭,设置中可开启(P1)。
- **keepalive**:默认 30s 全局空请求,可在设置调整(0=关闭)。
- **关闭确认**:关闭标签时若该连接仍有进行中的 SFTP 传输,提示"有 N 个传输任务"并让用户选择"取消传输并关闭 / 后台继续(断开连接但传输走独立重连)/ 取消"。
- **键盘**:Ctrl+滚轮缩放(5%–400%);选中即复制默认开启;右键行为可配(粘贴 / 显示菜单)。
- **广播输入(P2)**:进入同步模式后,输入同时发往勾选的多个终端,顶部显示醒目的"广播中"状态条防误操作。

### 6.4 SFTP 文件管理

**布局**:底部面板内左右双栏,左=本地、右=远程(连接后自动进入远端用户主目录);每栏含:路径栏(面包屑+直接输入)、工具条(上级、刷新、新建文件夹、删除、重命名、显示隐藏开关、视图切换)、文件列表。

**文件列表**:

- 列:图标(类型)、名称、大小(人类可读,KiB/MiB)、权限(如 `drwxr-xr-x`)、修改时间、所有者(若协议返回)。
- 目录优先排序;点击列头切换排序;名称支持中文 locale 排序。
- 虚拟滚动,单目录 >10,000 条目仍保持 60fps。
- 单击选中、Ctrl/Shift 多选、Ctrl+A 全选、右键上下文菜单、F2 重命名、Delete 删除、Enter 进入目录/预览。
- 刷新不丢失当前选择;目录变更(上传完成后)自动刷新目标目录。

**传输**:

- 拖拽:本地系统文件拖入远程栏=上传;远程条目拖出系统(桌面/资源管理器)=下载(P1,P0 至少支持拖入与右键下载);栏间拖拽按方向自动判定。
- 传输引擎:读/写分块(默认 32KiB,可调),并发请求(默认 8)提升大文件吞吐;目标:同一链路下单文件传输速度不低于 `sftp` 命令行的 80%。
- 队列:全局串行+并发可配(默认同时 2 个任务);任务状态机 `排队中 → 传输中 → 完成 | 失败 | 已取消`。
- 冲突:目标存在同名时弹框(覆盖 / 跳过 / 保留两者 / 取消),支持应用到本次剩余全部冲突。
- 取消:立即终止,保留已完成分片于临时文件(`.shelx-partial` 后缀),P1 的断点续传基于此实现。
- 目录递归:上传/下载目录时先建目录再逐文件入队,目录结构创建失败则该子树失败并入队报告。
- 失败重试:单任务网络类错误自动重试 2 次(指数退避),仍失败标记错误,可手动重试。

**操作一致性**:SFTP 操作失败(权限不足等)用 toast 展示服务端错误消息原文,列表不静默失败。

**远程文件编辑(P1)**:双击文本文件 → 下载到临时目录 → 调系统默认编辑器打开 → 监听文件修改 → 弹确认后回传。二进制文件双击仅提供"下载"。

### 6.5 服务端监控

**采集方式(免 Agent)**:后端经该连接的 exec channel 周期执行只读命令并解析,单连接一次采集合并为尽量少的命令调用(优先一次 shell 调用取全部指标),减少开销:

- CPU:`/proc/stat` 两次采样差值(总 + 每核),间隔=采样间隔
- 内存/Swap:`/proc/meminfo`
- 网络:`/proc/net/dev` 差值得速率
- 磁盘:`df -P -k`(容量)+ 读写 I/O 可选 `/proc/diskstats`(P2)
- 负载与 uptime:`/proc/loadavg` + `uptime -p` 或 `/proc/uptime`
- 系统信息(连接后一次性):`uname -a` + `/etc/os-release`

兼容性:目标为 Linux(物理机/虚机/容器);解析失败的单项指标显示"不可用"而非整体失败;非 Linux 目标(Unix/BSD)监控面板显示"不支持采集"占位,不影响终端与 SFTP。

**面板布局**(监控视图):

- 顶部信息条:主机名、发行版、内核、架构、uptime、连接用户名
- 图表网格(2 列,可拖拽换序 P1;统一使用 Recharts,实时更新关闭动画以避免高频重绘开销):
  - CPU:总占用面积图 + 每核迷你条形;悬浮显示数值
  - 内存:used/buffers/cache 分段堆叠 + Swap 单独小图
  - 网络:上下行双曲线,Y 轴自动适配 + 人类可读单位
  - 磁盘:每挂载点进度条(>85% 变橙,>95% 变红)
  - 负载:load 1/5/15 数字 + 迷你趋势
- 采样间隔下拉(2/5/10/30/60s),修改立即生效
- 会话内历史:环形缓冲保留最近 1 小时样本(5s 间隔约 720 点/指标,内存可承受),时间轴可拖动回看
- 断线:面板置灰 + "采集已暂停,等待重连"提示,重连后清空重新采集(不拼接断档数据)

**多服务器总览(P1)**:独立页签,已连接服务器各一张摘要卡(CPU 环、内存环、网速、状态色),点击卡片跳转该连接监控视图。

### 6.6 传输中心

底部面板第二个页签,列出所有传输任务(跨连接汇总):

- 列:方向图标(↑上传/↓下载)、文件名、源→目标路径、大小、进度条、速度、剩余时间、状态、操作(取消/重试/打开所在目录)
- 顶部:全局速率汇总、并发设置快捷入口、"完成后清除"按钮
- 任务完成保留记录(可配置自动清除),失败任务红色标注可重试
- 应用退出时若有进行中任务,退出确认框列明任务数

### 6.7 设置

分组表单页(Ctrl+, 打开),即时保存:

- **通用**:语言、主题(跟随系统/深/浅)、启动行为、自动更新开关
- **终端**:默认字体/字号/行距/光标样式、编码默认值、滚动缓冲行数、复制粘贴行为、关闭标签确认开关
- **连接**:keepalive 间隔、默认认证方式、host key 策略提示、钥匙串状态与"清理孤儿凭据"
- **传输**:并发任务数、分块大小(高级)、冲突默认策略、完成通知开关
- **监控**:默认采样间隔
- **关于**:版本、更新检查、开源许可、配置/日志目录入口

设置项变更作用范围:终端类设置对新开终端生效(已开终端提示可一键应用);其余即时生效。

## 7. 实现决策(Implementation Decisions)

### 7.1 技术栈(锁定)

| 层 | 选型 | 理由 |
|----|------|------|
| 框架 | Tauri 2 | 系统 WebView,包体与内存远小于 Electron |
| 前端 | Next.js(App Router,静态导出)+ React + TypeScript + shadcn/ui + Tailwind CSS | 用户指定;shadcn 基于 Radix + Tailwind,组件源码进仓库、完全可控可定制 |
| 状态管理 | Zustand | 轻量无样板代码,适合标签/会话/传输队列这类高频更新的客户端状态 |
| 终端 | @xterm/xterm + addon-fit + addon-webgl + addon-search | 行业标准 |
| 图表 | Recharts | React 声明式图表,与 shadcn/Tailwind 样式体系天然融合 |
| SSH 协议 | russh(客户端)| 纯 Rust、async、与 Tauri 的 tokio 运行时契合 |
| SFTP | russh-sftp | 与 russh 同生态,同一连接多 channel |
| 编码 | encoding_rs(WASM)| UTF-8/GBK 全覆盖,标准表 |
| 本地存储 | SQLite(rusqlite)| 连接树、传输历史;结构化且易扩展 |
| 凭据 | keyring crate | Windows 凭据管理器 / macOS Keychain / Linux Secret Service |
| 配置 | JSON 文件 | 设置与布局,便于人工检查 |

### 7.2 系统架构

```
┌───────────────────── 前端(Next.js/React,WebView)────────────────────┐
│ 连接管理器 │ 终端视图(xterm) │ 文件视图 │ 监控视图 │ 传输中心 │ 设置 │
└───────┬ command(请求/响应)────────┬─ Channel(高频流)─────────┘
        │                            │ terminal.data / transfer.progress / monitor.samples
┌───────▼────────────────────────────▼──────────────────────────┐
│                     Rust 核心(深模块)                          │
│  session-manager ── ssh-transport(russh 封装)                 │
│       │                 ├── pty(终端 channel)                  │
│       │                 ├── sftp-engine(文件 + 传输队列)        │
│       │                 └── collector(监控采集/解析)            │
│  conn-store(SQLite)   secret-store(keyring)   settings        │
└───────────────────────────────────────────────────────────────┘
```

**核心原则:一条 SSH 连接(一次认证)复用全部能力**。终端、SFTP、监控都只是该连接上的 channel;连接级状态(认证、编码配置、监控任务)统一由 session-manager 持有。

### 7.3 后端模块划分(深模块,可独立测试)

| 模块 | 职责 | 对外接口(概念) |
|------|------|----------------|
| `ssh-transport` | 唯一直接接触 russh 的模块:连接建立、认证(密码/私钥/键盘交互)、host key 校验回调、channel 开辟、keepalive、断连通知 | `connect(config) -> Session`;`session.open_pty()` / `open_sftp()` / `exec(cmd)`;认证与指纹事件回调 |
| `session-manager` | 会话生命周期与注册表:`SessionId → SshSession` 映射、状态机(连接中/在线/断开)、多终端路由(terminal_id → channel)、优雅关闭 | command 层的路由与状态查询 |
| `sftp-engine` | 文件操作(列表/增删改/chmod)+ 传输队列(并发调度、分块、进度回调、取消、重试、冲突计数) | 文件操作同步 command + 任务异步 Channel |
| `collector` | 监控采集:拼装只读命令、解析 /proc 文本、计算差值指标、按间隔调度、环形历史缓冲 | `start(session, interval, channel)` / `stop(session)` |
| `conn-store` | 连接树与分组的 CRUD、搜索、导入导出的持久层 | 领域对象读写,与 UI 无关 |
| `secret-store` | 凭据的存取与钥匙串引用管理、降级加密 | `put/get/delete(ref)` |
| `settings` | 应用设置与布局持久化 | 读写 + 变更通知 |

模块间依赖单向:command 层 → session-manager → ssh-transport → russh;collector 与 sftp-engine 依赖 ssh-transport 提供的 channel 抽象,不直接触碰 russh 类型。

### 7.4 前端模块划分

组件规范:交互组件(Dialog/Sheet/Tabs/DropdownMenu/Toast 等)统一使用 shadcn/ui 组合模式;超长列表(文件管理、传输中心)用 TanStack Virtual 做虚拟滚动。

| 模块 | 职责 |
|------|------|
| `connection-tree` | 侧栏树、搜索过滤、拖拽分组、右键菜单、编辑对话框(shadcn Dialog + Form) |
| `terminal-view` | xterm.js 的 React 封装(ref 命令式组件):挂载/写入/resize/编码解码/搜索/主题/断线横幅;每个 tab 一个实例,卸载即断 channel |
| `file-view` | 双栏文件管理器(虚拟列表)、拖拽、上下文菜单、chmod 对话框 |
| `transfer-center` | 任务列表、进度渲染、取消/重试 |
| `monitor-view` | Recharts 图表网格、采样控制、历史回看、系统信息条 |
| `tab-system` + `layout-store`(Zustand) | 标签管理、面板显隐、布局持久化 |
| `settings-view` | 设置表单(shadcn Form + Switch/Select) |

### 7.5 IPC 契约

**Commands(请求/响应,均为 Result 返回,错误带结构化 code+message)**

- 连接与配置:`connections.list/create/update/delete/duplicate/move`、`groups.*`、`connections.test_connect`、`settings.get/set`、`secrets.put/get/delete`
- 会话:`session.connect(conn_id) -> SessionInfo`、`session.close(session_id)`、`session.status_list()`
- 终端:`terminal.open(session_id, {cols, rows}) -> terminal_id`、`terminal.write(terminal_id, bytes)`、`terminal.resize(terminal_id, cols, rows)`、`terminal.close(terminal_id)`
- SFTP:`sftp.list(session_id, path) -> [FileEntry]`、`sftp.mkdir/rename/delete/setstat`、`sftp.upload(session_id, local, remote, policy, progress: Channel) -> task_id`、`sftp.download(...) -> task_id`、`sftp.cancel(task_id)`、`transfer.list/clear/retry`
- 监控:`monitor.start(session_id, interval_secs, channel: Channel<MetricsSample>)`、`monitor.stop(session_id)`

**Channels(高频单向流)**

- `terminal.data`:后端 → 前端,批量终端输出字节
- `transfer.progress`:后端 → 前端,任务进度(按 200ms 节流聚合)
- `monitor.samples`:后端 → 前端,指标样本

**Events(低频广播)**

- `session.status_changed`:连接状态机变化(前端更新标签圆点、横幅、监控置灰)
- `auth.prompt`:需要键盘交互输入(前端弹模态框应答)
- `hostkey.confirm`:首次指纹确认请求

### 7.6 核心数据结构(契约级形状)

```text
SessionInfo      { session_id, conn_id, status, server_info }
FileEntry        { name, file_type(dir|file|symlink), size, mtime, permissions, owner? }
MetricsSample    { ts,
                   cpu_percent, cpu_cores_percent[],
                   mem_total_kb, mem_used_kb, swap_total_kb, swap_used_kb,
                   net_rx_bps, net_tx_bps,
                   disks[{ mount, total_kb, used_kb }],
                   load1, load5, load15, uptime_secs }
TransferTask     { task_id, session_id, direction, local_path, remote_path,
                   total_bytes, transferred_bytes, status, error? }
```

SQLite 主要表:`connections`、`groups`、`transfer_history`(P1)。凭据不入库。

### 7.7 关键技术决策

1. **终端字节流端到端**:后端不解析/不转码终端数据,编码在前端按连接配置解码——避免后端字符串化破坏二进制与 TUI 程序。
2. **高频流必须走 Tauri 2 ipc::Channel**:绑定单一前端接收端,避免全局事件广播的序列化放大;终端输出按时间/大小批量聚合(≤16ms 或 64KB)。
3. **传输队列全局唯一**:跨连接统一调度,并发上限默认 2,单任务内部再并行 8 个分块请求——两层并发模型。
4. **host key 采用 TOFU + 变化阻断**:首次记录,之后不一致必须人工确认;指纹以 SHA256 展示。
5. **监控差值计算在后端**:两次 /proc 原始读数在前端只暴露计算后的样本,前端不做解析逻辑,保证采集逻辑可单测。
6. **凭据永不明文落盘**:钥匙串优先,降级方案为机器指纹派生密钥 AES-GCM 加密,且降级状态对用户可见。
7. **错误结构化**:所有 command 错误返回 `{code, message, source?}`,code 枚举(如 `AUTH_FAILED`、`HOSTKEY_CHANGED`、`PERMISSION_DENIED`、`NET_TIMEOUT`)供前端精确分支。
8. **Next.js 仅以静态导出形态使用**:构建产物为纯静态资源(`output: 'export'`),由 Tauri 直接加载;**禁用** SSR、Server Actions、API Routes、中间件等一切 Node 服务端能力,所有数据一律经 Tauri command/Channel 获取。开发期用 `next dev` 起开发服务器,配置为 Tauri 的 devUrl 实现热更新联调。

## 9. 测试决策(Testing Decisions)

**原则**:只测外部行为,不测实现细节;深模块接口稳定,优先在 Rust 层做高覆盖,Rust↔前端 IPC 层做契约测试,UI 做最小化冒烟。

| 模块 | 测试策略 |
|------|---------|
| `ssh-transport` | 集成测试:CI 内起容器化 sshd(固定测试密钥),覆盖密码/私钥/键盘交互认证、host key 变化阻断、命令超时、主动断连回调 |
| `collector` | 单元测试为主:以真实采集的 `/proc` 文本 fixture 驱动解析与差值计算(含边界:单核多核、缺 meminfo 字段、异常磁盘行);对容器 sshd 的端到端采集冒烟 |
| `sftp-engine` | 集成测试:对容器 sshd 的列表/建删改/上传下载 round-trip(校验哈希)、冲突策略、取消、并发调度 |
| `conn-store` / `settings` | 临时目录 SQLite/JSON 的 CRUD 单元测试 |
| `secret-store` | 钥匙串可用/不可用两分支的存取与降级测试 |
| IPC 契约 | command 参数/返回 JSON Schema 快照,防止前后端漂移 |
| 前端 | React Testing Library 组件测试:终端组件(编码切换、断线横幅)、传输中心状态渲染;手动测试清单覆盖弱网/服务器重启/GBK 服务器/超大目录 |
